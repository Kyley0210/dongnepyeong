# 동네평 (Firebase 무료 버전)

사장님이 가게를 올리고 손님이 리뷰를 남기는 동네 가게 리뷰 앱입니다.
**결제 카드 등록 없이 Firebase 무료(Spark) 요금제만으로 동작**하도록 만들었습니다.

## 무료 요금제에 맞춰 바꾼 점

Firebase 무료 요금제에서는 서버 함수(Cloud Functions)와 사진 저장소(Cloud Storage)를 쓸 수 없습니다.
(사진 저장소는 2026년 2월 3일부터 유료 Blaze 요금제가 필수가 되었습니다.) 그래서 아래처럼 바꿨습니다.

| 기능 | 무료 버전에서의 방식 |
|---|---|
| 가게·리뷰·답글·좋아요·즐겨찾기 | Firestore 데이터베이스 (무료) |
| 사진 | 사진을 압축해서 Firestore에 저장 (한 장 약 50~700KB) |
| 로그인 | 구글, 이메일 (무료). 카카오·네이버는 서버가 필요해서 빠졌습니다 |
| 번역 | 다른 언어로 쓴 글 아래에 **"Google 번역으로 보기"** 버튼 (무료) |
| 웹사이트 주소 | Firebase Hosting (무료, `https://프로젝트ID.web.app`) |

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `public/index.html` | 앱 화면 전체 (홈, 가게, 리뷰, 사장님 센터, 설정, 4개 언어) |
| `public/firebase-config.js` | **직접 채워야 하는 설정 파일** |
| `public/manifest.webmanifest`, `public/icons/` | 휴대폰 홈 화면에 추가할 때 쓰는 앱 정보와 아이콘 |
| `firestore.rules` | 데이터 보안 규칙 |
| `firebase.json`, `.firebaserc` | Firebase 배포 설정 |

## 1단계. 준비물 설치 (컴퓨터에서 한 번만)

1. **Node.js 20 이상**: https://nodejs.org 에서 LTS 버전을 설치합니다.
2. 터미널(Mac은 "터미널" 앱)을 열고 아래를 입력합니다.
   ```bash
   npm install -g firebase-tools
   firebase login
   ```

## 2단계. Firebase 프로젝트 만들기 (무료)

1. https://console.firebase.google.com → **프로젝트 추가** → 이름 예: `dongnepyeong`
   - 요금제는 **Spark(무료)** 그대로 둡니다. 업그레이드 안내가 나와도 누르지 않아도 됩니다.
2. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)** → 프로덕션 모드
3. **Authentication** → 시작하기 → **로그인 방법**에서 두 개를 켭니다.
   - 이메일/비밀번호
   - Google
4. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹(</>)** 으로 앱을 추가합니다.
   나오는 `firebaseConfig` 값을 `public/firebase-config.js` 의 `firebase: { ... }` 안에 그대로 붙여 넣습니다.
5. `.firebaserc` 파일의 `여기에-프로젝트-ID` 를 실제 프로젝트 ID로 바꿉니다.

## 3단계. 배포

터미널에서 이 폴더로 이동한 뒤 배포합니다.

```bash
cd ~/Desktop/dongnepyeong
firebase deploy
```

끝나면 `https://프로젝트ID.web.app` 주소가 나옵니다. 그 주소가 동네평입니다.
처음엔 가게가 없으니, 구글이나 이메일로 로그인한 뒤 **사장님 → 가게 등록**으로 첫 가게를 올려 보세요.

내 컴퓨터에서 먼저 보고 싶으면 `firebase serve` 를 실행하고 http://localhost:5000 을 열면 됩니다. (실제 데이터베이스에 연결됩니다)

## 무료 사용량 (하루 기준)

| 항목 | 무료 한도 | 동네평에서 쓰이는 곳 |
|---|---|---|
| 데이터 읽기 | 하루 50,000건 | 앱을 열 때 가게·리뷰·좋아요·즐겨찾기 문서를 읽고, 사진 1장을 볼 때 1건 |
| 데이터 쓰기 | 하루 20,000건 | 가게 등록, 리뷰, 좋아요, 즐겨찾기, 사진 올리기 |
| 저장 용량 | 총 1GB | 글은 아주 작고, 사진이 대부분을 차지 (사진 약 3,000~10,000장) |
| 웹사이트 전송량 | 월 10GB | 앱 화면 파일 (한 번 열 때 약 0.3MB) |

**대략적인 계산:** 앱을 한 번 열 때 읽는 양 ≈ (가게 수 + 리뷰 수 + 좋아요 수 + 즐겨찾기 수).
예를 들어 가게 50개, 리뷰 200개, 좋아요 300개, 즐겨찾기 100개면 한 번 열 때 약 650건이라
**하루 70번 정도 열면** 무료 읽기 한도에 닿습니다. 같은 기기에서 30분 안에 다시 열면 저장해 둔 내용을 써서 덜 읽습니다.

한도를 넘으면 **요금이 나가지 않고**, 그날 남은 시간 동안 읽기·쓰기가 막혔다가 다음 날 (미국 태평양 시간 자정) 다시 풀립니다.
사용자가 늘어 한도에 자주 닿으면 Blaze 요금제로 올리고, 지역별로 나눠 불러오도록 바꾸는 것을 권합니다.

사용량은 Firebase 콘솔 → **Firestore Database → 사용량** 탭에서 볼 수 있습니다.

## 어떻게 지켜지나요 (보안 규칙 요약)

- 누구나 가게·리뷰를 볼 수 있고, 쓰기는 **로그인한 사람**만 할 수 있습니다.
- 가게는 등록한 사장님만 고치고 지울 수 있습니다.
- 리뷰는 **쓴 사람만** 고치고 지울 수 있습니다. 사장님은 리뷰를 지울 수 없고 **답글만** 달 수 있습니다.
- 한 사람은 한 가게에 리뷰를 하나만 쓸 수 있고, 자기 가게에는 리뷰를 쓸 수 없습니다.
- **같은 동네·같은 주소의 중복 등록은 서버 규칙에서 막힙니다.** (주소가 없으면 같은 동네·같은 이름)
- 사진은 자기가 올린 것만 지울 수 있고, 한 장에 1MB 미만만 저장됩니다.

## 알아 둘 한계

- 지금은 앱이 열릴 때 가게(최대 1,000개)와 리뷰(최대 3,000개)를 한꺼번에 불러옵니다. 무료 읽기 한도 때문에, 가게가 수백 개를 넘으면 지역별로 나눠 불러오도록 바꿔야 합니다.
- 즐겨찾기·좋아요 기록은 개수를 세기 위해 공개로 읽힙니다.
- "주변" 탭은 내 동네 주소 기준입니다. 실제 GPS·지도는 앱으로 감쌀 때 추가하는 것을 권합니다.
- 나이 표시는 화면 언어 기준입니다 (한국어 19+, 일본어 20+, 영어·중국어 18+).

## 나중에 유료(Blaze)로 올리면 켤 수 있는 것

- 카카오·네이버 로그인 (서버 함수 필요)
- 리뷰 자동 번역 (서버 함수 + Claude API 키)
- 사진을 Cloud Storage에 저장 (더 크고 많은 사진, 더 빠른 로딩)

Blaze도 무료 사용량은 그대로 포함되고, 넘는 만큼만 요금이 나갑니다. 필요해지면 이 기능들을 다시 붙여 드릴 수 있습니다.

## 다음 단계: 앱스토어·구글플레이 출시 (Capacitor)

웹 앱을 그대로 감싸 iOS·Android 앱으로 만들 수 있습니다.

```bash
npm init -y
npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
npx cap init 동네평 kr.dongnepyeong.app --web-dir public
npx cap add ios
npx cap add android
npx cap open ios        # Xcode에서 실행·제출 (Apple 개발자 계정 연 99달러)
npx cap open android    # Android Studio에서 실행·제출 (Google Play 개발자 계정 25달러, 1회)
```

앱스토어 등록 비용(Apple 연 99달러, Google 1회 25달러)은 Firebase와 별개로 듭니다.
